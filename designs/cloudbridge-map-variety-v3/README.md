## 桥为什么能接上

- 岛面和桥面共享同一套世界网格、同一高度与同一摄像机投影，不能再分别手工摆图片和机器人路径点。
- 每座岛的可行走地表为3×3格；图中的相邻岛中心相隔6格，因此中间固定有3格桥缺口。岛岸边界与桥块边界逐格重合。
- 桥块是低矮实心桥面，木头和石头只改变材质与通行规则，不改变几何高度；接好后形成连续道路，不出现悬浮台阶或跨空隙滑过去。
- 机器人从实际可站立的格子移动到相邻格，动画脚底跟随路面；缺桥和木桥风口会挡住移动。
- 自然岩柱与装饰仅位于路面下方或边缘，不遮住桥口与实际落脚格。

## 玩家如何参与

1. **搭桥阶段**：选建材，补缺口，拆除和撤销退回材料；大按钮为“开始过桥”。
2. **过桥阶段**：用四个斜向方向按钮亲自移动，分别对应等距视角的四个网格方向；键盘WASD／方向键对应同一组移动。没有默认自动寻路代替玩家走。
3. **岔路由玩家决定**：自己去拿星晶、折返回岔口、选择另一条路，观察哪里需要石桥。
4. **回到搭桥**：保留已搭的桥、回到本关起点；按钮旁的说明明确这一行为，方便重排资源后再走。
5. 无倒计时、掉落惩罚或付费提示。第6关先收集指定星晶才可抵达终点；其余星晶为可选挑战。

## 设计阶段检查

设计脚本枚举了各图的桥段子集，验证起点到终点（第6关还要经过星晶岛）存在库存允许的连接方案；每个桥段均是水平或纵向的三格缺口。六关均通过该规则检查。该检查是**设计数据演算**，不是游戏实现或实际手感验收。

实现后仍须验证实际格子可走、每座桥对齐岸边、每个方向键与画面方向一致、星晶条件、材料退款、旧存档保留，以及逐关的运行截图。新地图进度单独记录，不把旧变体关的通关记录直接当成新地图已完成。

依据项目 [AGENTS.md](../../AGENTS.md)，新增场景布局与操作界面须先展示并获得明确确认，再修改游戏代码与资源。本目录保留确认稿；实现使用同一份地图定义和同一套网格投影。

## 文件与生成方式

示意图为代码绘制的SVG，经macOS AppKit按指定画布渲染为PNG，未使用生成式图片，不代表新的美术风格。`draw_design.py` 同时产生地图JSON与SVG；`render.swift` 将SVG以完整宽高渲染，最终交付为 `six-maps.png`、`manual-crossing.png`。
